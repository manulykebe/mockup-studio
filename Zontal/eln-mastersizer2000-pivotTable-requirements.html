Executive Summary
This document specifies an interactive pivot-table experience for reviewing Mastersizer 2000 measurement data in an ELN context. Users can configure row, column, and value dimensions; reorder fields; filter visible row and column values; rename displayed labels without losing their source names; choose appropriate aggregation behavior; and save a reproducible view in the URL. Version 0.2 formalizes the expanded value aggregation model, including numeric statistics, unit-aware calculation behavior, and a plain multi-value table presentation.

1. Business Context & Objectives

  • Business Need: Laboratory users need to inspect repeated Mastersizer 2000 measurements in a compact, configurable view while preserving the relationship between source data and displayed labels.
  • Primary Goal: Provide an Excel-like pivot experience that supports rapid comparison of measurements, controlled aggregation, and reproducible view configuration.
  • Data Integrity Goal: Calculations MUST only be performed on values originating from Scalar Double Datum. Text values originating from Scalar String Datum MUST remain visible through joined or tabular presentation rather than being treated as numeric data.
  • Target Persona: Analytical Scientists, QC Analysts, and Lab Managers reviewing particle-size measurements in the ELN.

2. Scope & Workflow

The interface provides two complementary views of the same source table:

  1. Flat view: Displays the source records and source fields without pivot manipulation.
  2. Pivoted view: Displays grouped records according to user-selected Rows, Columns, and Values field zones.

The pivot workflow is:

  1. Review fields in the Available list.
  2. Drag fields into Rows, Columns, or Values zones.
  3. Reorder fields within a zone.
  4. Configure visibility, value order, labels, and aggregation.
  5. Save the current configuration as a URL-reproducible view.

4. Detailed Functional Requirements

4.1. View and Field-Zone Management (FR-VIEW)

Req ID Feature Status Priority Requirement Description
FR-VIEW-01 Flat/Pivoted Views BASELINE MUST The interface MUST provide Flat view and Pivoted view controls. Pivoted view MUST be the initial active view.
FR-VIEW-02 Available Fields BASELINE MUST The Available list MUST contain source fields not assigned to Rows, Columns, or Values. A field MUST appear in only one zone at a time.
FR-VIEW-03 Drag-and-Drop Assignment BASELINE MUST Users MUST be able to drag a field into a zone and reorder it relative to existing fields. The resulting order MUST control grouping or value-field order.
FR-VIEW-04 Multiple Values Chips ADDED v0.2 MUST The Values zone MUST support multiple field chips concurrently. Each Values chip MUST retain its own aggregation selection and display label.
FR-VIEW-05 Collapsible Field Panel BASELINE SHOULD The field panel SHOULD be collapsible and draggable. Its collapsed state and position SHOULD remain usable without changing pivot results.

4.2. Rows and Columns Configuration (FR-DIM)

Req ID Feature Status Priority Requirement Description
FR-DIM-01 Row Grouping BASELINE MUST Rows fields MUST group records by the selected source values. Hidden row fields MUST continue to participate in grouping even when their output column is hidden.
FR-DIM-02 Row Visibility BASELINE MUST Each Rows chip MUST expose a visibility checkbox. Unchecking it MUST hide only the rendered row column and MUST NOT remove its grouping behavior.
FR-DIM-03 Column Value Expansion BASELINE MUST Each Columns field MUST be expandable to show distinct values. Distinct values MUST be reorderable and individually hideable.
FR-DIM-04 Value-Order Preservation BASELINE MUST Custom ordering of distinct column values MUST be preserved in the rendered pivot column order.
FR-DIM-05 Column Value Labels ADDED v0.2 MUST Users MUST be able to rename a distinct value chip without changing the raw source value used for grouping, ordering, or visibility. The custom label MUST be used only for display headers.

4.3. Chip Renaming and Label Integrity (FR-LABEL)

Req ID Feature Status Priority Requirement Description
FR-LABEL-01 Inline Rename Trigger ADDED v0.2 MUST Double-clicking a label on a Rows, Columns, Values, or expanded column-value chip MUST replace the label with an inline text input.
FR-LABEL-02 Dual Label Display ADDED v0.2 MUST After renaming, the new label MUST appear in black above the original label. The original label MUST remain visible in grey below it so source meaning is never lost.
FR-LABEL-03 Reset Behavior ADDED v0.2 MUST A reset control MUST appear immediately to the left of the original label. Activating it, or submitting an empty label, MUST restore the original display.
FR-LABEL-04 Keyboard Completion ADDED v0.2 MUST Enter or blur MUST commit a rename. Escape MUST cancel the edit. Dragging MUST resume after editing.
FR-LABEL-05 Safe Text Rendering ADDED v0.2 MUST User-entered labels MUST render as literal text and MUST NOT be interpreted as HTML or script.
FR-LABEL-06 Displayed Header Propagation ADDED v0.2 MUST Custom Rows labels MUST update row headers. Custom column-value labels MUST update pivot column headers. Custom Values labels MUST be used in multi-value cell labels.

4.4. Value Aggregation (FR-AGG)

Req ID Feature Status Priority Requirement Description
FR-AGG-01 Join BASELINE MUST Join MUST concatenate values using the configured delimiter. For multiple raw values, the result MUST be prefixed with ⋯; a single raw value MUST remain unmarked.
FR-AGG-02 First BASELINE MUST First MUST return the first value in source order. When multiple values were reduced, the result MUST be prefixed with ①.
FR-AGG-03 Table ADDED v0.2 MUST Table MUST render multiple raw values as one value per row in a plain, unformatted table. A single raw value MUST render as plain text without a containing table. No aggregation symbol MUST be shown for Table.
FR-AGG-04 Numeric Option Availability CHANGED v0.2 MUST Average, Std Dev, and Count MUST be offered when the selected field contains numeric-capable source data. The UI labels SHOULD identify them as numeric-only options.
FR-AGG-05 Average ADDED v0.2 MUST Average MUST calculate the arithmetic mean of numeric Scalar Double Datum values and prefix the result with Ø.
FR-AGG-06 Standard Deviation ADDED v0.2 MUST Std Dev MUST calculate sample standard deviation using numeric Scalar Double Datum values and prefix the result with σ. A cell with fewer than two numeric values MUST return an empty result.
FR-AGG-07 Numeric Count ADDED v0.2 MUST Count MUST count numeric Scalar Double Datum values and prefix the result with #.
FR-AGG-08 Non-Numeric Fallback CHANGED v0.2 MUST If a selected Value cell contains text from Scalar String Datum, Average, Std Dev, and Count MUST NOT calculate. They MUST fall back to joined raw values, including the normal ⋯ marker when more than one value is joined.
FR-AGG-09 Unit Preservation CHANGED v0.2 MUST Average and Std Dev MUST append the applicable source unit after the calculated number, for example Ø 55.075 µm and σ 0.0028 µm. Count MUST remain unitless.

4.5. Multiple Values Fields (FR-MULTI)

Req ID Feature Status Priority Requirement Description
FR-MULTI-01 Combined Output Column ADDED v0.2 MUST When more than one Values field is selected, each column group MUST produce one output column rather than one column per Values field.
FR-MULTI-02 Name/Value Cell Table ADDED v0.2 MUST Each combined cell MUST contain a compact table with one row per Values field: the displayed field name in the first column and the aggregated content in the second column.
FR-MULTI-03 Stable Raw Keys ADDED v0.2 MUST Combined rendering MUST NOT alter grouping, ordering, hidden-value filtering, or raw cell identity. These operations MUST continue to use original source values and field names.

4.6. URL Persistence (FR-STATE)

Req ID Feature Status Priority Requirement Description
FR-STATE-01 Save View BASELINE MUST The Save current view action MUST serialize the active pivot configuration into the pivot URL parameter without reloading the page.
FR-STATE-02 Layout Restoration BASELINE MUST On load, valid Rows, Columns, Values, aggregation, visibility, order, expansion, and panel state MUST be restored.
FR-STATE-03 Rename Restoration ADDED v0.2 MUST Field labels and per-column-value labels MUST be serialized and restored. Restored labels MUST affect display only and MUST NOT replace raw data keys.
FR-STATE-04 Backward Compatibility CHANGED v0.2 SHOULD Saved views created before v0.2 SHOULD load with default labels and existing aggregation behavior when the new state properties are absent.

5. Data Dictionary & Aggregation Contract

Source Field Role Data Type Rules Example
Scalar Double Datum Numeric source Decimal number Eligible for Average, Std Dev, and Count. Unit is taken from the corresponding Unit field. 55.073
Scalar String Datum Text source String Not eligible for numeric calculations. Values MUST be joined or shown with Table aggregation. MAL1098134
Unit Numeric qualifier String Appended to Average and Std Dev results when present. µm
Datum Label Column dimension String Distinct values become pivot column groups and can be reordered, hidden, or relabeled. D [3, 2] - Surface weighted mean
Value Derived Values field String or numeric-with-unit display value Derived from Scalar Double Datum plus Unit, or Scalar String Datum when no double datum exists. 55.073 µm

6. Acceptance Criteria

Scenario 1: Numeric Average with Unit

Given the Values zone contains the derived field Value And a pivot cell contains Scalar Double Datum values 55.073 and 55.077 with Unit "µm" When the user selects "Average (num only)" Then the cell displays "Ø 55.075 µm" And the raw source values remain unchanged.

Scenario 2: Non-Numeric Fallback

Given a pivot cell contains Scalar String Datum values "MAL1098134" and "MAL1098134 bis" When the user selects "Average (num only)" or "Count (num only)" Then no numeric calculation is performed And the cell displays the joined text prefixed with "⋯" And the text values are not discarded.

Scenario 3: Table Aggregation

Given a pivot cell contains more than one source value When the user selects "Table" Then the cell displays one raw value per row in a plain, unformatted table And no Table icon or other aggregation symbol is displayed When the cell contains only one source value Then the value is displayed as plain text without a containing table.

Scenario 4: Multiple Values Fields

Given the Values zone contains "Value" and "Index" When the pivot is rendered Then each column group contains one output column And each populated cell contains a two-column table And the first column contains the Values chip name And the second column contains its aggregated content.

Scenario 5: Rename and Restore a Chip

Given the user double-clicks the "Sample Identifier" Rows chip label When the user enters "Sample ID" and presses Enter Then "Sample ID" is shown in black And "Sample Identifier" remains visible in grey beneath it And the reset control appears immediately to the left of the grey original label And the rendered row header is "Sample ID" When the user saves the view and reloads the URL Then both labels and the rendered header are restored.

7. Non-Functional Requirements

  • NFR-01: Data Integrity: Raw source field names and values MUST remain available as stable keys for grouping, sorting, filtering, and persistence.
  • NFR-02: Accessibility: Interactive controls MUST expose meaningful labels. Rename inputs MUST be keyboard operable. Reset controls MUST identify the original label.
  • NFR-03: Security: User-entered chip labels MUST be rendered as text and MUST NOT create executable or interpreted HTML content.
  • NFR-04: Compatibility: The shared pivot utility MUST preserve existing behavior for callers that do not use v0.2 label, multi-value, or aggregation features.
  • NFR-05: Readability: The new name/value tables MUST remain legible when multiple Values fields are selected. A single-value cell MUST avoid unnecessary table markup.
