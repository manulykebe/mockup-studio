Executive Summary
This document defines the complete business, functional, non-functional, and technical interface requirements for the Zontal SDMS Measurement Import Plugin/Modal embedded within an Electronic Lab Notebook (ELN). The interface enables laboratory scientists to query analytical measurement records stored in Zontal (filtered by Instrument Class, Instrument ID, Sample ID, and Measurement Date), review matching measurement datasets with rich metadata, select individual or batch records across pages, and seamlessly import the raw/processed scientific datasets into their active ELN experiment.

1. Business Context & Objectives

  • Business Need: Analytical lab workflows require researchers to link raw scientific instrument datasets (e.g., Calorimeter, Particle sizer, XRPD, Spectrophotometer) directly from the centralized Zontal SDMS repository into ELN experiment binders to maintain GxP compliance, auditability, and data integrity.
  • Primary Goal: Provide an intuitive, multi-step search-and-select user dialog that eliminates manual file transfers, enforces mandatory search criteria, supports flexible mathematical date range logic, and guarantees deep-link URL state reproducibility.
  • Target Persona: Analytical Scientists, Quality Control (QC) Analysts, and Lab Managers using the ELN to document experimental procedures and link instrument data.

2. Interface Overview & Workflow Architecture

The interface is structured as a two-stage sequential Accordion Panel Workflow:

  1. Stage 1: Select Measurement (Search & Filter Panel): User defines search criteria (Instrument Class, Instrument ID, Sample ID, Date logic). Executing "Show results" queries Zontal and transitions to Stage 2.
  2. Stage 2: Select Result (Data Grid & Selection Panel): User reviews matching measurement datasets in a paginated, sortable Data Grid, selects required measurement IRIs (URN UUIDs), and executes "Import results in ELN".

3. Detailed Functional Requirements

3.1. General Layout & Accordion Panel Controls (FR-PANEL)

Req ID Requirement Name Priority Requirement Description
FR-PANEL-01 Stepped Accordion Pattern MUST The interface MUST consist of two collapsing panels: 1. Select Measurement (Panel 1) and 2. Select Result (Panel 2). Expanding one panel MUST automatically collapse the other panel.
FR-PANEL-02 Initial Panel State MUST Upon initial load (without pre-existing URL parameters), Panel 1 MUST be expanded. Panel 2 MUST be collapsed and visually/functionally disabled (data-disabled="true", header disabled, summary showing "Complete step 1 first").
FR-PANEL-03 Dynamic Header Summary MUST Panel 1 header MUST display a real-time summary string of active filters separated by bullet characters ( • ), e.g., Calorimeter • CAL-002 • sample 15222759 • between 2025-01-01 and 2025-01-31. If no filters are defined, display "No filters applied".
FR-PANEL-04 Filter Change Invalidation MUST If any filter criterion in Panel 1 is modified after results have been fetched, Panel 2 MUST immediately revert to disabled/collapsed state, clearing all existing record selections until "Show results" is clicked again.

3.2. Step 1: Filter Criteria Specification (FR-FILTER)

Req ID Field Name Type Validation & Business Rules
FR-FILT-01 Instrument class Required Dropdown Select Mandatory field (marked with a red asterisk *). 3.3. Step 2: Measurement Results Grid & Selection (FR-GRID)

Req ID Feature Priority Functional Requirements & Data Grid Rules
FR-GRID-01 Data Grid Display MUST The system MUST render matching measurement records using a DataTables layout with the following columns:
  1. Checkbox Column: Multi-select checkbox. Header contains "Select All Visible" checkbox.
  2. Iri: Zontal URN identifier (e.g., urn:uuid:1ed4b622-447c-45ba-b4bf-26445c96ecaf).
  3. Index: Zero-based numerical sequence index.
  4. Measurement Time: ISO 8601 timestamp formatted as YYYY-MM-DD HH:mm:ss. Must support chronological sorting.
  5. Sample Identifier: Alphanumeric sample name string (e.g., 15222759 BDH 1, 14GN973 - Average).
FR-GRID-02 Pagination & Controls MUST MUST support pagination with selectable page lengths (5, 10, 15, 20; default: 10). MUST include an instant search box filtering across all data columns except checkbox.
FR-GRID-03 Selection State Management MUST The system MUST maintain selected record URN IRIs in a set object that persists across page navigation, sorting, and live filtering.
FR-GRID-04 Header Checkbox Logic MUST The header checkbox (#selectAllVisible) controls ONLY the visible rows on the current page:
  • Checking selects all visible rows on current page.
  • Unchecking deselects all visible rows on current page.
  • Reflects an indeterminate state when some, but not all, visible page rows are selected.
FR-GRID-05 Live Status Counter MUST Grid footer status text MUST display live counts of total selected records vs. visible page selections:
Showing 1 to 10 of 113 entries — 3 selected (2 on this page).
FR-GRID-06 ELN Import Action MUST An "Import results in ELN" button MUST be rendered at the bottom right of Panel 2. The button MUST be disabled when 0 records are selected, and enabled when $\ge 1$ records are selected. Clicking syncs state to URL parameters and submits selected IRIs to the host ELN context.

3.4. Deep Linking & URL State Persistence (FR-URL)

Req ID Parameter Description & Behavior
FR-URL-01 Bidirectional URL Sync All active user selections MUST automatically synchronize with browser URL parameters using window.history.replaceState without reloading the page.
FR-URL-02 URL Parameter Schema The URL state schema MUST adhere to:
  • instrumentClass: e.g. Calorimeter
  • instrumentId: e.g. CAL-002
  • sampleId: e.g. 15222759
  • dateOperator: equal | before | after | between
  • dateNot: true | false
  • dateValue1: ISO Date string (YYYY-MM-DD)
  • dateValue2: ISO Date string (YYYY-MM-DD)
  • selected: Comma-separated URN IRIs (e.g., urn:uuid:1ed4b622...,urn:uuid:604e49b7...)
FR-URL-03 Auto-Restoration & Direct Execution When the page loads with query parameters, the application MUST:
  1. Display the full overlay loader modal ("Loading measurements...").
  2. Populate all filter controls and execute dependent dropdown fetches.
  3. Restore checkbox selections for valid URN IRIs.
  4. Automatically execute search ("Show results") and open Panel 2 directly.

4. Acceptance Criteria (Gherkin Scenarios)

Scenario 1: Mandatory Instrument Class Validation & Dependent Fetch

Given the user opens the Zontal ELN Import Interface And no URL parameters are present Then Panel 1 ("1. Select Measurement") is expanded And Panel 2 ("2. Select Result") is disabled and collapsed And the "Show results" button is disabled And the Instrument ID dropdown is disabled with text "Select an instrument class first" When the user selects "Calorimeter" from the Instrument Class dropdown Then a loading spinner appears next to Instrument ID for 650ms And Instrument ID becomes enabled with options ["Any instrument ID", "CAL-001", "CAL-002", "CAL-014"] And the "Show results" button becomes enabled.

Scenario 2: Date Filter Operator & Input Visibility

Given the user is configuring the Measurement Date filter in Panel 1 When the user selects the "Between" radio operator Then both Date Value 1 and Date Value 2 inputs are visible with the "and" label When the user toggles the "Not" button to active (aria-pressed="true") And inputs dates "2025-01-01" and "2025-01-31" Then the Panel 1 summary header displays "not between 2025-01-01 and 2025-01-31".

Scenario 3: Multi-Page Record Selection & Import Activation

Given the user has executed "Show results" and Panel 2 is expanded And the "Import results in ELN" button is disabled (0 selected) When the user checks 2 records on Page 1 Then the status text shows "2 selected (2 on this page)" And the "Import results in ELN" button becomes enabled When the user navigates to Page 2 and checks 1 record Then the status text updates to "3 selected (1 on this page)" And navigating back to Page 1 preserves the checkboxes for the 2 previously selected records.

Scenario 4: Deep Link State Restoration

Given the user navigates to the page with URL: ?instrumentClass=Calorimeter&instrumentId=CAL-002&selected=urn:uuid:1ed4b622-447c-45ba-b4bf-26445c96ecaf Then the loading overlay modal appears immediately And Instrument Class is set to "Calorimeter" And Instrument ID is loaded and set to "CAL-002" And search is automatically triggered And Panel 2 expands showing matching results with URN urn:uuid:1ed4b622... pre-selected And the "Import results in ELN" button is enabled.

6. Non-Functional Requirements (NFRs)

  • NFR-01: Performance & Latency Feedback: All asynchronous lookups (fetching Instrument IDs, searching measurements) MUST provide explicit visual feedback (inline spinners and full-screen semi-transparent modal overlay). Search queries MUST return within 1.0 second.
  • NFR-02: Accessibility (WAI-ARIA Compliance):
    • All interactive elements MUST support full keyboard navigation (Tab, Shift+Tab, Enter, Space, Esc).
    • Dynamic accordions MUST use correct aria-expanded and aria-controls attributes.
    • Modals MUST implement focus trapping, background backdrop dimming, and Esc key dismissal.
    • Screen reader labels MUST be supplied for icon buttons and grid checkboxes via aria-label.
  • NFR-03: Responsive Design & Layout: Interface MUST render seamlessly on screen resolutions from 1024x768 up to 4K displays without breaking table columns or control alignments.
  • NFR-04: Cross-Browser Compatibility: Supported browsers include Microsoft Edge (latest 2 versions), Google Chrome (latest 2 versions), Safari (latest 2 versions), and Firefox (latest 2 versions).
