Generic ASM Field Extraction: Procedure Synopsis

Goal: turn any Allotrope ASM measurement file into a linearized dataset (rows of label, value, unit) by joining it against a reviewable field catalog, without hardcoding field names per instrument.

Always, first

  1. Read the measurement file.
  2. Extract $asm.manifest (a URI string at the top level).

If the manifest is new (no cached catalog yet)

  1. Resolve the manifest URI: strip the scheme and host, then look up in/manifest/<remaining path>.json (e.g. the manifest http://purl.allotrope.org/manifests/ftir/REC/2024/12/ftir.manifest resolves to in/manifest/ftir/REC/2024/12/ftir.manifest.json), matched by its @id, then read its json-schemas[0] URI.
  2. Resolve that schema URI the same way: strip the scheme and host, then look up in/schema/<remaining path> (e.g. http://purl.allotrope.org/json-schemas/adm/ftir/REC/2024/12/ftir.schema resolves to in/schema/adm/ftir/REC/2024/12/ftir.schema), matched by its $id.
  3. Run scripts/schema_catalog_builder.js on that schema to produce a catalog of every candidate field, with value: null and an include flag pre-set (true for scalar/quantity, false for datacube).
  4. Manually review the catalog: adjust include flags as needed, then save it under a name keyed to the manifest in out/ (e.g. out/<manifest-name>.catalog.json). Never reuse the reserved name field_catalog.schema.json - that file is the JSON Schema validating the catalog format itself, not a catalog.

If the manifest is already known (cached catalog exists)

  1. Resolve the manifest URI the same way, to confirm it matches the cached catalog's manifest.
  2. Load the existing cached catalog directly - skip regeneration.

Always, last: the "join"

  1. Run node scripts/dataset_extractor.js in/<measurement-file> out/<catalog-file> -o out/dataset.csv.
  2. For each catalog entry with include: true, resolve its path against the live measurement file and emit a label, value, unit row.

Key clarifications

  • The manifest does not contain a schema directly - it only points to one via a URI, which must be matched to a local .schema file by $id.
  • The join ignores the catalog's own value field entirely; only path and include matter. The actual value always comes fresh from the measurement file being processed.
  • Catalogs must be cached per manifest, under distinct filenames, to avoid collisions with reserved schema files.

Folder layout

  • in/ - measurement files (read-only inputs).
  • in/manifest/ - manifest JSON files, stored under a path that mirrors their $asm.manifest URI (host stripped, path kept, .json appended).
  • in/schema/ - ASM schema files, stored under a path that mirrors their $id URI (host stripped, path kept).
  • scripts/ - the three Node.js tools described below.
  • out/ - generated catalogs and the linearized dataset (all script outputs).

Tooling map

Script Input Output Purpose
scripts/catalog_builder.js in/<measurement file> (.asm.json) out/field_catalog.json Discover fields from an actual data file (values populated)
scripts/schema_catalog_builder.js in/schema/<schema file> (.schema) out/schema_field_catalog.json Discover fields from a schema (no data yet, values null)
scripts/dataset_extractor.js in/<measurement file> + out/<catalog file> out/dataset.csv Join catalog against a measurement file, emit linearized rows
