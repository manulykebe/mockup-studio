Master Template Manual

Controlled Word templates for Q-Regulate

A practical guide to installing, using, approving, versioning, and maintaining the Word Master Template implemented by the SSG-MC-v1 VBA project.

Audience: users and administrators Platform: Microsoft Word on Windows Storage model: local junction / Q-Documents

1. Overview

Q-Regulate is a controlled Word Master Template. It attaches metadata to templates and documents, exposes document-management actions in a custom Sopra Steria ribbon tab, protects approved documents, and creates new versions rather than allowing approved files to be overwritten.

What it controls

Document identity, type, numbering, sequence, status, version, ownership, approval roles, field updates, and file naming.

What it does not replace

It does not replace SharePoint permissions, backup, records retention, or the organisation's approval policy. Those remain operational responsibilities.

Primary source

The reusable code is in Master Template/SSG-MC-v1. The Master Template is under Master Template/SSG-MT-v1 (where versioning applies).

Recognition rule

A document is treated as a Q-Regulate document when it contains the custom property document_guid.

TerminologyIn this manual, “template” means a Word .dotm or .dotx file, while “document” means a working or approved .docx file created from a template.

2. Core concepts

Status model

Available status values

ImportantApproval is a status transition implemented by the ribbon. It is not a substitute for a documented business approval decision. Apply the organisation's approval policy before pressing Approve.

3. Requirements

  • Microsoft Word on Windows with macro execution permitted for the trusted template location.
  • Access to the Q-Regulate storage location and permission to read and write its files.
  • The local path C:\Sopra Steria\Q-Regulate\ available to the code. The implementation uses this path as its fixed root.
  • For reference repair, access to the VBA project object model must be enabled in Word's macro security settings.
  • For production use, the expected document library folder must be available at C:\Users\<username>\Sopra Steria\Q-Regulate - Q-Documents.
Security boundaryOnly enable “Trust access to the VBA project object model” when required by the administrator. It is needed by the reference-maintenance macro, not by ordinary document editing.

4. Installation and environment setup

Synchronize with SharePoint

Switch the Q-Regulate junction

The supplied junction.bat switches C:\Sopra Steria\Q-Regulate between the production Q-Documents folder and a development folder. Run it from an elevated command prompt if Windows requires administrator rights to create or remove the junction.

Confirm the production folder exists.The script expects C:\Users\<username>\Sopra Steria\Q-Regulate - Q-Documents. If it is missing, the script stops.
Run junction.bat. It displays the active location and offers production, development, or removal.
Select the target. Choose 1 for production or 2 for C:\Sopra Steria\Q-Regulate (dev).
Verify the active location. The script highlights the current junction target. Never develop directly against production content.

Install the template reference

The Master Template must reference the Master Code Template project under the reference name MasterTemplateCode. The maintenance macro VoegSjabloonReferentieToe first removes broken references and then adds:

C:\Sopra Steria\Q-Regulate\Master Template\SSG-MC\SSG-MC-v1.dotm

After adding or repairing the reference, close and reopen the Master Template. The Master Template's document events check that the reference exists before forwarding open, new, and close events.

Reference failureIf the Master Template reports “Template Reference Missing”, check the junction target, confirm that SSG-MC-v1.dotm exists at the expected path, enable VBA project-model access if the repair macro needs it, and run the reference repair macro.

Numbering rules

  • For Word templates, the number is normally company-code + "-" + type-code, for example SSG-SOP.
  • For ordinary documents, the number is normally company-code + "-" + type-code + "-" + three-digit sequence, for example SSG-SOP-004.
  • Changing the type code recalculates the number. The version lookup then scans the matching folder and base filename, so the version refreshes for the new type.

6. Document lifecycle

DraftEditable content and metadata.
ApproveAssigns Approved and effective date.
Read-onlyApproved file is protected.
New versionCreates a new draft file.

Open

When a controlled document opens, the system compares its version with the highest matching version found in its parent folder. If a newer version exists, Word displays a warning with the path to the newest match. Drafts are unlocked for editing; non-drafts are protected for reading.

New document

Creating a new document routes through the save interceptor. On first save, the source must be approved and must not have type code MT or MC. The document-management form collects its sequence, metadata, and initial version before saving it to the controlled path.

Approve

For a draft, choose Sopra Steria > Approve. The system sets document_status to Approved, sets document_effective_date to the next day, updates fields, applies read-only protection, saves, and refreshes the ribbon.

Close

Controlled documents are locked and saved on close unless the internal __close flag has been set. This keeps approved documents protected when leaving Word.

7. User workflows

Create a new controlled document

Open an approved ordinary template. Do not start from an MT or MC master template.
Enter content while the document is Draft. Use the template's styles and metadata fields.
Save for the first time. The system opens the Document Management form. Enter or confirm the sequence, title, and responsible roles.
Review the generated number, version, and target path. The filename uses the document number and -v version suffix.
Approve when the business review is complete. The document becomes read-only and can no longer be saved over directly.

Create a new version

Open the current approved file. The Create new version command is enabled only for approved documents.
Choose Sopra Steria > Create new version. The form reads the existing metadata and calculates the next version from matching files.
Update the title, sequence where permitted, and role fields. A new document GUID is generated and protection is kept in sync with it.
Save the new file. The system refuses to overwrite an existing target file. The new version starts as Draft.
Review and approve the new version. Repeat the approval step after the revision is complete.

Create a new template from the Master Template

Open an approved Master Template. The Create new template button is enabled when the active document's type code is MT.
Choose Sopra Steria > Create new template. Enter the readable type and its short code. Codes MT and MC are reserved.
Confirm the generated target. New templates are copied to C:\Sopra Steria\Q-Regulate\Templates\<company-code>-<type-code>\ and use a .dotm extension.
Review the copied template. The system regenerates its GUID, writes metadata, updates fields, removes the starter instruction section, and saves it.

Update metadata

For a draft, choose Sopra Steria > Metadata. Edit the enabled owner, author, reviewer, approver, management approver, or title fields and save. Metadata is intended for draft documents. The special username evanneste receives elevated metadata availability according to the ribbon callback.

How the highest version is found

GetHighestVersionOfFile scans the parent folder and matches files with the same base name and extension using the pattern BASE-vX.ext or BASE-vX.Y.ext. It returns the highest numeric version and the form uses that value plus one. If the folder or matching files do not exist, the starting value is 1.

Keep versions togetherDo not rename a version file independently of its metadata, move it to a different naming structure, or mix unrelated files in the same base-name folder. The open-time “latest version” check depends on this convention.

9. Editing and formatting tools

The Home tab replaces parts of Word's standard formatting surface with style-oriented controls. The custom controls apply Word styles rather than direct character formatting.

Style controls
ControlStyle appliedBehavior
BoldStrongToggles the style on the selection.
ItalicEmphasisToggles the style on the selection.
UnderlineUnderlinedToggles the style on the selection.
StrikeStrikethroughToggles the style on the selection.
SuperscriptSuperscriptToggles the style on the selection.
SubscriptSubscriptToggles the style on the selection.
Clear FormatNormalToggles the paragraph style back to Normal.

Format selected tables

The table-formatting command is enabled when the selection contains at least one table. It applies Plain Table 1, sets the first row as a heading row, enables row banding, applies No Spacing to table paragraphs, and autofits the table to its content and window.

Style dependencyThe formatting code expects the named Word styles Strong, Emphasis, Underlined, Strikethrough, Superscript, Subscript, Normal, No Spacing, and Plain Table 1. Do not delete or rename them in a controlled template.

10. Administration and maintenance

Safe promotion procedure

  1. Switch the junction to the development location.
  2. Make and test changes against copies of templates and documents.
  3. Verify open, new, save, approve, new-version, print, field-update, and close behavior.
  4. Check that the Master Template still has the MasterTemplateCode reference.
  5. Switch the junction to production only during a controlled deployment window.
  6. Keep a backup of the previous template and code-template files before replacement.

Reference and diagnostics macros

Useful maintenance entry points
MacroPurpose
VoegSjabloonReferentieToeRemoves broken VBA references and adds the Master Code Template reference if it is missing.
VerwijderOngeldigeVerwijzingenRemoves broken VBA project references.
ListAllCustomPropertiesPrints custom property names to the Immediate window.
getAllCustomDocumentPropertiesPrints custom property names for a document.

Backups and recovery

  • Back up the production Q-Documents location and the complete Master Template package.
  • Preserve approved files as immutable records; create a new version for changes.
  • If a GUID or protection password becomes inconsistent, work from a known-good copy and use the controlled GUID regeneration path. Do not edit document_guid directly on a protected document.
  • When testing version behavior, use a separate development junction so generated files cannot be mistaken for production records.

11. Troubleshooting

Symptoms and corrective actions
SymptomLikely causeAction
The Sopra Steria tab is missing.Macros did not run, the code template is not loaded, or the document is not recognized as controlled.Confirm the file is a macro-enabled template/document, reopen Word, check the reference, and confirm document_guid exists.
“Template Reference Missing”.The Master Template cannot find the MasterTemplateCode reference.Check the junction and expected file path, enable VBA project access if needed, then run VoegSjabloonReferentieToe.
Approve is disabled.The current status is not Draft.Open the Metadata form while the document is editable and verify the status property.
Create new version is disabled.The current status is not Approved.Only approved documents can create a new version. Check document_status.
First save closes the document.The source is not approved, or its type code is MT or MC.Start from an approved ordinary template. Master templates are not document sources.

Changing the type code gives the old version.The target number or folder did not refresh, or old code is running.Confirm the current SSG-MC-v1 code uses the fixed -v1 probe path and scans the parent folder before rebuilding the target path.

Important implementation notes

  • The storage root is hard-coded as C:\Sopra Steria\Q-Regulate\; changing it requires a coordinated code change in the relevant modules and deployment script.
  • SharePoint URLs containing sites\Qregulate\QDocuments\ are converted to the local Q-Regulate root. URL decoding currently handles %20 spaces.
  • Protection uses the document GUID as its password. GUID regeneration must unprotect, replace the property, and re-protect in one operation.
  • The standard Word print commands are intercepted so fields are updated at print time and hidden text is excluded.
  • Some cleaning macros are present in the source but their ribbon controls are intentionally hidden and disabled in the current ribbon XML.
  • The code is VBA and uses Windows APIs and Office object-model types. This manual therefore describes a Windows Word deployment, not a cross-platform Office deployment.
Operational principleApproved files are outputs, not working copies. Revise through a new draft version, preserve the approved file, review the new content, and approve the replacement deliberately.
